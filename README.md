# Arogio Health Backend

NestJS + TypeScript API with PostgreSQL and Drizzle. Business functionality lives in **feature modules**; shared database definitions and operational tools have separate, clearly named locations.

## Structure

```text
database/
  migrations/             # Ordered SQL files, journal and snapshots
scripts/
  database/               # Read-only inventory/diagnostics and local migrator
  local/                  # Isolated local API runner
  verification/           # Smoke/account/hosting checks
  previews/               # Admin composition preview tooling
src/
  app.module.ts           # Composes the feature modules
  bootstrap/              # HTTP setup and static-asset routing
  configuration/                 # Environment validation
  common/                 # Shared guards, errors, logging and helpers
  infrastructure/         # External provider boundaries
  database/
    schema/               # Drizzle table definitions, grouped by feature
    seeds/                # Explicit seed entry points
    migrate.ts            # Production PostgreSQL migration runner
  modules/
    authentication/ user-accounts/ personal-wellness/ care-directory/
    health-resources/ meditation-library/ home-dashboard/ jeeva-assistant/
    administration/ system-health/ system-status/
test/                     # Cross-module HTTP and database integration tests
dist/                     # Generated deployment output; edit src instead
```

Inside a feature, start at `<feature>.module.ts` or its `README.md`. Request handlers are in `controllers/`, business logic in `services/`, validation in `requests/` and `responses/`, and database access in `repositories/` where that feature already has a repository. Specialist helpers use `domain/`, `imports/`, `content/` or `integrations/`. Unit tests stay next to the code they exercise. Empty placeholder folders are not created.

## Common commands

Use Node.js **22.9 or newer**, as required by `package.json`.

```sh
npm ci
npm run build
npm run start:local:validation   # Disposable local PGlite database
npm run start:local              # Persistent local PGlite; uses .env.local
```

For a configured PostgreSQL connection:

```sh
npm run db:list                  # Locate/list SQL files; no database connection
npm run db:generate -- --name=describe_your_change
npm run db:check                 # Validate migration metadata
npm run db:migrate               # Applies pending migrations to DATABASE_URL
```

See [database/README.md](database/README.md) before applying migrations or running a seed. The SQL history keeps its existing filenames, contents and journal ordering so previously deployed databases retain the same migration identity.

```sh
npm run lint
npm test
npm run test:e2e
npm run test:migrations
```

Detailed setup, environment and authentication explanations are in [docs/guides/setup-and-authentication.md](docs/guides/setup-and-authentication.md). The current architecture is described in [docs/MODULES.md](docs/MODULES.md); [IMPLEMENTATION.md](IMPLEMENTATION.md) retains earlier delivery decisions.

`dist/` is generated by `npm run build`. This repository tracks it for the existing shared-hosting deployment, so rebuild it after source changes. SQL migrations must be deployed alongside it in `database/migrations/`. Do not edit generated JavaScript as the source of truth.
